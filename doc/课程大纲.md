# 「电商问数」智能体 30 节课从零开发课程大纲

> 目标：不照抄代码，跟着每节课**自己动手写**，从空目录一步步搭出一个
> 「自然语言问数」AI Agent（Text-to-SQL），打通「元数据知识库构建 →
> 混合检索 → LangGraph 多阶段推理 → SQL 生成/校验/执行 → 前端流式联调」全链路。
>
> 参考项目：`D:\项目\agent\shopkeeper-agent`（真实代码在 D 盘仓库里，可随时对照，但尽量先自己写）

---

## 课程总览（7 个阶段，30 课）

```text
阶段一  认知与环境          第 1-4 课    搞懂做什么 + 装好一切
```

## 阶段一：认知与环境（第 1-4 课）

### 第 1 课 · 项目概览与目标定位
- **学什么**：这个项目到底做什么、解决什么痛点、技术栈全景、能力边界
- **核心知识点**
  - "自然语言问数"的 5 步：听懂问题 → 召回上下文 → 写 SQL → 校验执行 → 返回结果
  - 解决 3 个幻觉问题：表选错、字段选错、指标口径错
  - 技术栈：LangGraph / LangChain / Qdrant / Elasticsearch / MySQL / TEI / FastAPI / React
- **动手任务**：写一段 Markdown，用自己的话描述「用户问 → agent 答」的输入输出
- **验收**：能向别人一句话讲清这个项目是干什么的

### 第 2 课 · 数仓基础：事实表与维度表
- **学什么**：业务库 vs 数仓、星型模型、事实表/维度表/度量/维度
- **核心知识点**
  - 教学数仓 `dw` 的 5 张表：`fact_order`（事实）+ 4 张 `dim_*`（维度）
  - `fact_order` 只存外键 + 度量值（order_quantity / order_amount）
  - 为什么问数要 JOIN 维度表
- **动手任务**：手写 `docker/mysql/dw.sql`，设计这 5 张表并插入模拟数据
- **验收**：`docker compose` 起来后 MySQL 里的 `dw` 库能查到订单数据

### 第 3 课 · 系统整体架构
- **学什么**：本项目两条主线 + 四大存储的分工
- **核心知识点**
  - 主线一「元数据知识库构建」：YAML → MySQL/Qdrant/ES/TEI
  - 主线二「自然语言问数」：LangGraph 编排 + FastAPI + SSE + React
  - 存储分工：MySQL 存权威元数据，Qdrant 存字段/指标向量，ES 存字段取值，dw 存业务数据
- **动手任务**：画一张架构图（纸上/PPT 均可），标清每个组件的数据流向
- **验收**：能说清「为什么问数既需要 MySQL 又需要 Qdrant、ES」

### 第 4 课 · 开发环境与基础服务搭建
- **学什么**：装好所有前置工具，把 5 个基础服务跑起来
- **核心知识点**
  - `uv`（Python 3.14 依赖管理）、Docker Desktop、Node + `pnpm`
  - `docker-compose.yaml` 起 5 个服务：MySQL(3306) / ES(9200) / Kibana(5601) / Qdrant(6333) / Embedding(8081)
  - MySQL 首次启动自动执行 `meta.sql` 和 `dw.sql`
  - 下载 Embedding 模型：`BAAI/bge-large-zh-v1.5`
- **动手任务**：`docker compose up -d`，用 `docker ps` 确认 5 个容器 Up
- **验收**：浏览器能打开 Kibana(5601) 和 Qdrant(6333) 面板

## 阶段二：工程骨架与配置（第 5-7 课）

### 第 5 课 · 项目结构设计与分层理念
- **学什么**：`app/` 各子包职责，以及 client/repository/service/entity/model 分层思想
- **核心知识点**
  - 目录职责：agent/api/clients/conf/core/entities/models/prompt/repositories/scripts/services
  - 分层调用链：`节点 → repository(业务) → client(技术)`；`entity(业务对象) ↔ model(ORM) ↔ mapper`
- **动手任务**：用 `uv` 初始化项目（`pyproject.toml`），建好所有空目录
- **验收**：目录结构与参考项目 `app/` 一致

### 第 6 课 · YAML 配置与 OmegaConf 加载
- **学什么**：`app_config.yaml` + `OmegaConf` + `dataclass` 强类型配置
- **核心知识点**
  - 运行参数：数据库连接、Qdrant/ES/Embedding 地址、LLM 模型名与 Key
  - `OmegaConf.load()` 读 YAML → dataclass；`${oc.env:LLM_API_KEY}` 环境变量注入
  - 为什么配置要放 YAML 而不是写死在代码
- **动手任务**：写 `conf/app_config.yaml` 和 `app/conf/app_config.py`
- **验收**：能 `print(app_config.mysql.host)` 打印出正确值

### 第 7 课 · 元数据知识清单设计
- **学什么**：`meta_config.yaml` —— 描述数仓「有哪些表/字段/指标」
- **核心知识点**
  - 三类元素：tables（表+role）、columns（字段+role+alias+examples）、metrics（指标+relevant_columns+alias）
  - 字段 role：primary_key / foreign_key / measure / dimension
  - 指标口径：GMV = SUM(order_amount)，AOV = AVG(...)
- **动手任务**：写 `conf/meta_config.yaml` 和 `app/conf/meta_config.py`
- **验收**：YAML 里完整描述了 dw 库的全部表、字段、2 个指标

### 第 16 课 · 字段向量写入 Qdrant

### 第 17 课 · 指标向量 + 字段值全文索引

## 阶段五：问数智能体工作流（第 18-24 课）

### 第 18 课 · LangGraph 入门
- **学什么**：StateGraph、State、Context、节点与边的概念
- **核心知识点**
  - `StateGraph(state_schema=..., context_schema=...)`
  - State（业务中间结果）vs Context（共享资源）的区别
  - `add_node` / `add_edge` / `add_conditional_edges` / `compile`
- **动手任务**：写个 3 节点的玩具图跑通
- **验收**：理解 state 如何随节点流转、context 如何注入

### 第 19 课 · 工作流骨架与状态定义
- **学什么**：把 12 个节点注册进图，定义完整 `DataAgentState` 和 `DataAgentContext`
- **核心知识点**
  - `graph.py`：START → extract_keywords → 三路召回 → merge → filter → add_context → SQL 闭环 → END
  - `state.py`：query/keywords/三类召回/table_infos/metric_infos/date_info/db_info/sql/error
  - `context.py`：6 个 repository + embedding_client 的类型声明
- **动手任务**：写 `state.py`、`context.py`、`graph.py`（先空节点骨架）
- **验收**：图能 `compile()` 不报错，`get_graph().draw_mermaid()` 能画出流程图

### 第 20 课 · 关键词抽取节点 extract_keywords
- **学什么**：jieba 分词 + LLM 扩展关键词
- **核心知识点**
  - `jieba.analyse.extract_tags(query, allowPOS=...)` TF-IDF 抽词
  - `keywords = list(set(keywords + [query]))` 合并去重
  - LLM 扩展：把「销售总额」扩展成「销售金额」等
  - `runtime.stream_writer` 推 `progress` 消息
- **动手任务**：写 `extract_keywords.py`
- **验收**：输入「统计华北地区的销售总额」，输出含「华北/销售/总额」的关键词列表

### 第 21 课 · 字段召回节点 recall_column
- **学什么**：关键词 → Embedding → Qdrant 相似度检索 → 字段去重
- **核心知识点**
  - `runtime.context["column_qdrant_repository"]` / `["embedding_client"]` 取资源
  - `await embedding_client.aembed_query(keyword)` → `repository.search(embedding)`
  - 用 `column_info.id` 去重（多关键词命中同字段）
  - LLM 先扩展字段语义再召回（extend_keywords_for_column_recall）
- **动手任务**：写 `recall_column.py`
- **验收**：能召回 `order_amount`、`region` 等候选字段

### 第 22 课 · 指标召回 recall_metric + 取值召回 recall_value（并行三路）
- **学什么**：`recall_metric.py`（Qdrant）和 `recall_value.py`（ES）
- **核心知识点**
  - 指标召回用 metric_qdrant；取值召回用 value_es_repository
  - 三路通过「从 extract_keywords 分别连三条边」实现并行
  - 并行是 LangGraph 默认：同一时间多条出边会并发执行
- **动手任务**：写这两个节点，并接好并行边
- **验收**：一次请求三路召回同时返回字段、指标、取值

### 第 23 课 · 召回合并与上下文构建
- **学什么**：`merge_retrieved_info` + `filter_table` + `filter_metric` + `add_extra_context`
- **核心知识点**
  - merge：三路召回结果汇总成候选表/指标/值
  - filter_table / filter_metric：LLM 判断筛掉无关表和指标
  - add_extra_context：补 date_info（当前日期/季度）和 db_info（方言/版本）
- **动手任务**：写这 4 个节点并接边
- **验收**：merge 后 state 里 table_infos / metric_infos 齐全

### 第 24 课 · SQL 生成与执行闭环
- **学什么**：`generate_sql` → `validate_sql` → `correct_sql` → `run_sql`
- **核心知识点**
  - generate_sql：`prompt | llm | StrOutputParser` 产出纯 SQL 文本
  - validate_sql：用 `EXPLAIN` 校验，正确则走 run_sql，错误写回 `state["error"]`
  - `add_conditional_edges`：`path=lambda state: "run_sql" if state["error"] is None else "correct_sql"`
  - correct_sql：带错误信息重写 SQL；run_sql：在 dw 库执行
- **动手任务**：写完这 4 个节点，接好条件分支
- **验收**：`graph.py` 的 `__main__` 自测能完整跑通一条问数

## 阶段六：API 接口与流式（第 25-27 课）

- **学什么**：`/api/query` 路由、`StreamingResponse`、SSE 协议
- **核心知识点**
  - FastAPI 应用入口 `main.py`；路由 `app/api/routers/query_router.py`
  - `StreamingResponse` 逐条推送；SSE 的 `data:` 格式

### 第 26 课 · QueryService 与依赖注入
- **学什么**：`query_service.py` 组装 context 并驱动 graph；`dependencies.py` 依赖注入；`lifespan.py` 生命周期
- **核心知识点**
  - `get_column_qdrant_repository()` 等工厂函数创建依赖
  - `DataAgentContext(...)` 把 6 个资源绑定起来（你之前问的"映射"就在这）

  - lifespan：应用启动/关闭时 init/close 客户端
- **动手任务**：写 query_service + dependencies + lifespan + schema
- **验收**：`POST /api/query` 能完整返回一次问数结果流

### 第 27 课 · LLM 接入与 Prompt 管理
- **学什么**：统一 LLM 客户端 + Prompt 模板统一加载
- **核心知识点**

  - `prompt_loader.py` + 模板文件：SQL 生成/修正/过滤/关键词扩展等 prompt

- **动手任务**：写好 llm.py 和全部 prompt 模板
