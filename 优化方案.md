## 一、结论（TL;DR）

**底子很好，这是同体量项目里少见的 "架构意识" 作品**：错误是数据、降级矩阵、质量门、轮数闸、SQL 只读防护、ast 白名单求值、分层清晰 —— 这些是很多生产级 Agent 项目都没有的。**没有发现真实可利用的注入 / 密钥泄露漏洞，但存在 3 个必须先处理的部署级隐患**（明文数据库密码、CORS 全放开无鉴权、无 .gitignore），以及一批 "架构承诺未兑现" 的债（InMemorySaver、safe\_call 占位、交付路径双写、零测试）。

按优先级处理：**P0 安全 3 项（1 天）→ P1 架构债 8 项（3\~5 天）→ P2 工程债 8 项（1\~2 周随开发做）**。

## 二、架构现状与亮点（先肯定，再动手）

### 2.1 图拓扑（graph/graph.py 为唯一权威）



```
START → task_parser →(route_intent 三路)
  ├─ clarify → clarify_interrupt ⇄ task_parser（澄清 ≤2 轮闸）
  ├─ quick   → quick_answer → deliver（RAG 直答旁路）
  └─ analyze → planner → query_executor → join → compute
              → supervisor(5 worker 子 agent) → writer → reviewer
              →(route_after_validate) deliver | fixer → deliver → END
```

### 2.2 值得保留的设计（勿在优化时误删）



| 设计             | 位置                                                                  | 评价                                |
| -------------- | ------------------------------------------------------------------- | --------------------------------- |
| 「错误是数据不是异常」    | 全链路 degraded 标记、errors 用 `operator.add` 累加、节点 try/except 兜底         | 核心哲学，贯彻彻底                         |
| 三路意图分流 + 澄清轮数闸 | route\_intent.py、clarify\_interrupt.py（MAX\_CLARIFY=2）              | 语义优先级正确：quick > clarify > analyze |
| 质量门 + 修正闸      | reviewer.py + fixer.py（MAX\_FIX=2）                                  | 规则校验不调 LLM，超限如实标注降级交付             |
| 成本 / 死循环闸      | tool\_call\_limit(15) / model\_call\_limit(30)                      | 防烧 token 的硬闸                      |
| SQL 只读防护       | query\_executor：非 SELECT 直接拒绝                                       | 防注入的第一道门                          |
| 受控 SQL 拼装      | planner：字段名来自指标定义表 + 日期正则校验                                         | 字段白名单 + 格式校验双保险                   |
| 安全计算           | utils/safe\_calc.py：ast 白名单求值，不 eval                                | 杜绝公式注入，单一实现两处复用                   |
| 混合检索降级矩阵       | retriever.py：dense+BM25→RRF→rerank 钩子→逐层降级                          | 矩阵完整，任何一层挂都有出路                    |
| supervisor 强约束 | SYSTEM\_PROMPT：「禁止编造数字 / 委托时原样写入指标数据」                               | 直击子 agent 隔离模式下编造数据的痛点            |
| writer 固定字段渲染  | 不调 LLM，数字代码渲染                                                       | 报告数字 100% 可溯源                     |
| 分层             | clients / repositories / rag / tools / nodes / workers / middleware | 各层只依赖下层，命名一致性好                    |
